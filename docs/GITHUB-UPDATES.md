# Проверка обновлений StudHub Launcher через GitHub Releases

Источником версий стал официальный репозиторий `Agarych-ilya/StudHub_launcher`.
Лаунчер при открытии и затем каждые 30 минут запрашивает:

`GET https://api.github.com/repos/Agarych-ilya/StudHub_launcher/releases/latest`

Сравнивает стабильный `tag_name` с собственной версией (`src-tauri/Cargo.toml`) по SemVer. Поддерживаются теги `v0.4.9` и `0.4.9`. Черновики и prerelease не учитываются. Релиз без файла установщика для текущей ОС (.exe на Windows, .dmg на macOS, .AppImage на Linux) не объявляется доступным обновлением. Новая версия показывает баннер на главной и кнопку в настройках. Кнопка открывает официальную страницу релиза в системном браузере. Ошибка сети или отсутствие релиза (HTTP 404) не мешают запуску Minecraft. Старые версии не предлагаются как обновления.

**Важно:** GitHub Releases API служит для уведомления о новых версиях, а не как доверенный источник для запуска файлов. Не скачивайте и не исполняйте неподписанный EXE из JSON API. Имеющийся механизм автоматической установки Windows остаётся доступен только с проверяемым Ed25519-манифестом, SHA-256 и явным доверенным HTTPS-хостом (`docs/AUTO-UPDATES.md`). Для macOS пользователь открывает GitHub Release и устанавливает DMG вручную. Для бесшовных macOS-обновлений потребуется добавить отдельную, подписанную и проверенную схему, macOS code signing/notarization, проверку на настоящем Mac.

## Как публиковать обновления

1. Загрузите исходники (включая модпак через Git LFS) в GitHub; одного workflow в репозитории недостаточно.
2. Обновите *одинаковую* версию в `package.json`, `src-tauri/Cargo.toml`, `src-tauri/tauri.conf.json`.
3. Соберите и проверьте релизные пакеты Windows (`.exe`) и macOS (`.dmg`).
4. Создайте тег `v0.4.9`, опубликованный GitHub Release (не draft и не prerelease), приложите соответствующие установщики. На macOS workflow прикрепляет DMG к релизу при запуске по тегу.
5. При следующем запуске версия 0.4.8 увидит релиз 0.4.9, предложит открыть страницу и скачать сборку для нужной платформы. Для Windows можно **дополнительно** настроить подписанный манифест по инструкции `docs/AUTO-UPDATES.md`.

Выпуск `v0.4.8` при установленной `0.4.8` уведомлений не показывает. Пока GitHub Releases пуст, настройки пишут, что релизов нет.
