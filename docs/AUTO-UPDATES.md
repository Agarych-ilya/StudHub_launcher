# Автообновление StudHub 0.4.7

Механизм реализован для Windows: при старте и затем каждые 30 минут, когда игра закрыта, лаунчер получает подписанный manifest. Новая версия скачивается, проверяется Ed25519 и SHA-256, лаунчер закрывается; отдельный процесс ждёт его завершения, запускает NSIS с /S и после успешной установки открывает новую версию. Игровые данные остаются в своей папке. При занятой сборке установка откладывается. Ошибка источника сохраняет текущую версию.

Адрес источника пока не задан. Поэтому автоматическая проверка новых выпусков не включена в готовом установщике: нужен постоянный публичный HTTPS-хостинг с прямыми ссылками без редиректов. Папка Drive с модпаком не является источником обновлений самого лаунчера.

## Один раз для владельца

1. Создать отдельный Ed25519-ключ вне каталога проекта: `node tools/manifest.mjs keygen --out /PRIVATE/launcher-key.pem`. Хранить его у владельца, не отправлять игрокам.
2. Выбрать HTTPS-адреса для manifest и установщиков. Пример ниже содержит YOUR_HOST — заменить на действующий хостинг.
3. Подготовить выпуск:

```sh
node tools/launcher-release.mjs --exe StudHubLauncher-0.4.7-Setup.exe --version 0.4.7 --url https://YOUR_HOST/releases/StudHubLauncher-0.4.7-Setup.exe --update-url https://YOUR_HOST/launcher-manifest.json --key /PRIVATE/launcher-key.pem --out release
```

4. Загрузить установщик, затем опубликовать launcher-manifest.json. Для следующих версий использовать тот же ключ.
5. Положить полученный deployment.json в корень проекта перед сборкой NSIS через tools/installer.nsi: он войдёт в установщик. Уже установленному клиенту можно один раз положить deployment.json рядом с StudHubLauncher.exe и перезапустить. Отдельные кнопки подключения в интерфейс не возвращены.

HTTPS trusted_origins и публичный ключ фиксируют разрешённые источники. Поле installer должно быть nsis. Адреса должны отдавать файл напрямую, без перенаправления на вход или страницу скачивания. Windows может показать стандартное системное предупреждение для неподписанного издателем EXE. Автоматическая установка на настоящем Windows в этой среде не проверена.

## Общий онлайн и спавн

Общий онлайн обновляется каждые 15 секунд через Minecraft status ping к 148.253.208.254:25589. Он сообщает число игроков всего сервера и не содержит координат.

Чтобы показывать людей именно на спавне, серверный мод NeoForge должен на основном потоке раз в 1–5 секунд считать игроков в выбранном измерении в радиусе R от точки спавна. Например: X/Z = 0/0, радиус 64 блока, считать только мир overworld. Число и время сохраняются в потокобезопасном снимке; HTTP-обработчик читает снимок без обращения к игровым объектам из сетевого потока. Через HTTPS выдаётся:

```json
{"players":12,"updated_at":1791619200}
```

updated_at — настоящий Unix timestamp секунды, а число — результат подсчёта, не статический пример. В deployment.json задать spawn_status_url, добавить HTTPS origin в trusted_origins. Можно добавить --spawn-url в команду генерации выпуска. Лаунчер показывает «На спавне: N», если ответ свежий (не старше 30 секунд); при сбое не подставляет ноль и не выдаёт общий онлайн за число людей на спавне.

Сам мод и HTTPS-публикация на вашем сервере пока не установлены: нужны доступ к серверу, выбранные координаты/радиус и адрес API. Не публиковать данные игроков или права управления — только агрегированное число.
